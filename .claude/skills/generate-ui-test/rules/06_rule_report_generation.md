# Phase 5: 报告生成规则

## R5.1 报告路径

生成报告输出至 `report/generate_report/generation_report.html`（HTML 格式，自包含）。

## R5.2 报告格式

| 层级 | 格式 |
|------|------|
| 整体 | 自包含 HTML（内联 CSS + JS，无外部依赖） |
| 模块 | `<details class="module">` 可收起，有探测失败的模块默认展开 |
| 用例 | `<details class="case">` 可收起，有失败步骤的用例默认展开 |
| 步骤 | `<table>` 表格，9 列 |
| L3 关键字 | 主行可展开（`<details>`），内部子步骤缩进显示 |

**表格列定义**：

| 列名 | 内容 | 说明 |
|------|------|------|
| 步骤 | 序号 | 步骤编号（1, 2, 3…），L3 子步骤为 4.1, 4.2… |
| 关键字 | keyword | 步骤使用的关键字名称，L3 子步骤带 └ 前缀 |
| 描述 | desc | 步骤描述文本 |
| 输入数据 | 变量引用 | 步骤的输入参数（变量引用形式，如 `${data.url}`） |
| 实际数据 | 解析值 | 从 data/ YAML 解析出的实际数据值 |
| 元素定位 | 变量引用 | 定位器变量引用（如 `${page.btn_add}`） |
| 实际定位器 | 解析值 | 从 pages/ YAML 解析出的实际 XPath 定位器 |
| 探测结果 | 状态图标 | 见 R5.3 |
| 备注 | 来源+修改建议 | 见 R5.4, R5.5 |

## R5.3 探测结果标记（三种状态）

| 标记 | 含义 |
|------|------|
| ✅ | 探测成功（verified=true） |
| ❌ | 探测失败（无匹配元素），备注列显示修改文件路径 |
| — | 不需要探测的步骤（open_url、refresh、wait_for_time、数据引用等） |

**L3 关键字**：主行标记为 ✅(L3) 或 ❌(L3)（取内部子步骤最差结果），子步骤各自独立标记。

## R5.4 探测来源备注

探测成功的步骤在备注列标注来源：
- 知识库匹配 → 备注 "知识库"
- L3 关键字内部 → 备注 "L3:{workflow_name}"
- AI 补充生成 → 备注 "AI生成"

## R5.5 失败步骤备注建议

探测失败的步骤必须在备注列提供修改建议，包括建议修改的文件路径（pages YAML）。

## R5.6 实际数据/实际定位器列变量解析完整

报告步骤表格中的"实际数据"列和"实际定位器"列必须展示变量解析后的真实值：

- **实际数据**：从 `data/` YAML 解析出的 `${group.field}` 对应的实际数据值
- **实际定位器**：从 `pages/` YAML 解析出的 `${group.field}` 对应的实际 XPath 定位器

如果变量无法解析（在 pages/data 中找不到对应 key），显示原始变量引用并标注 `[未解析]`。
