# Phase 6: 运行验证规则

## R6.1 运行报告路径

运行报告输出至 `report/run_report/` 目录。

## R6.2 失败分类处理

| 失败类型 | 判断标准 | 处理方式 |
|---------|---------|---------|
| 执行问题 | Timeout、element not found、locator 错误 | 自动修复：调整定位器/关键字，重新运行 |
| 断言问题 | 断言失败但前置步骤全成功 | 报告给用户：可能是系统 bug |

## R6.3 自动修复策略（最多 3 轮）

- Timeout → 用 probe 重新探测该元素
- element not found → 用 probe 重新探测
- fill 超时 → 检查是否 TinyMCE，改用 `frame_fill_value`
- `:visible` 相关 → 改用纯 XPath 定位，不使用 `:visible` 伪类

## R6.4 自学习机制

### 失败模式学习
- 记录失败的定位器、关键字、错误信息
- 分析失败原因，更新知识库或规则
- 相同失败模式累计 3 次 → 自动标记为"需人工确认"

### 成功模式学习
- 用例运行 PASS → 记录成功的定位器和操作序列
- 成功的定位器加入知识库，提升下次探测成功率
- 成功的操作序列记录为"推荐模式"

### 用户纠正学习
- 用户手动纠正的 XPath → 直接更新知识库
- 用户确认的修复方案 → 记录为"已验证修复"
